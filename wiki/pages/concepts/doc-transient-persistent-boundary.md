# 文档时态边界：Transient vs Persistent

> 类型：concept ｜ 来源：Issue #32（intent/llm-wiki.md 设计决策 E）｜ 更新：2026-09-04

## 是什么

仓库里的文档按生命周期分两类，**边界不清会导致知识丢失或三套真相**：

| | 时态文档（Transient） | 长青知识（Persistent） |
|---|---|---|
| **载体** | `intent/` `spec/` `plan/` | `wiki/` |
| **回答的问题** | 这次需求做什么（为什么做/怎么做/怎么算成） | 这个库一直怎么被 AI 正确地改 |
| **生命周期** | 以 PR 合并为终点，移入 `archive/` 即"死" | 跨需求持续演化，不随归档消失 |
| **写入者** | 人 + AI（Gate 流程） | AI 写、人审（走 PR） |

## 核心机制：归档 → 编译

需求收尾（文档移入 `archive/`）时，**必须**把其中的决策、教训、反模式编译进 `wiki/` 页面——否则知识随归档沉睡，新会话的 AI 无法继承（如"hooks 为何用 Python""REVIEW 为何不阻塞"这类深度决策只存在于历史对话与 archive 里）。

判定一条知识该不该编译进 wiki：**它跨需求仍成立吗？**
- "这次 spec 的口径怎么定的" → 不编译（这次怎么做）
- "为什么检测必须确定性、不靠 AI 判断" → 编译（以后一直怎么改）

## 边界（防三套真相）

| 载体 | 职责 | 读取方式 |
|---|---|---|
| 根 `AGENTS.md` | 常驻总纲（一页内） | 每次会话自动注入 |
| `.qoder/rules/` | 操作约束 | 按 glob/决策按需加载 |
| `intent/spec/plan` | 时态文档（本需求） | 按需求读取 |
| `wiki/` | 长青知识（本模式） | 查询先读 `wiki/index.md` |

wiki 只收 AGENTS.md 与 rules 装不下的**深度知识**，不重复它们的职责；反之，wiki 是它们"背后的为什么"。
