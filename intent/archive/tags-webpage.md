# 意图：待办清单支持标签 + 网页页面

## 意图 / 作者 / 状态 / 来源
- 意图：给待办加标签、能按标签筛选，并提供一个网页页面来查看和操作待办
- 作者：demo｜状态：已批准｜来源：—（示例需求，未走 Issue）

## 问题
待办一多就全混在一起找不着。用户只想看"工作"的，或者只想看"家里"的，现在做不到。
另外目前只能靠 curl / 命令行调 API，没有页面，不会用 API 的人没法使用。

## 预期成果
- 新增待办时可以带标签（最多 3 个）
- `GET /todos?tag=工作` 只返回带该标签的待办，标签匹配不区分大小写（`tag=工作` 与 `tag=Work` 等价）
- 没带标签的待办行为不变，照常按优先级排序
- 新增一个网页页面（`web/index.html`），能：
  - 列出未完成待办（按优先级排序）
  - 输入标题新增待办（可填标签，最多 3 个）
  - 按标签筛选列表
  - 把某条标记为完成
  - 展示"已完成"列表（只读），标记完成的条目移到那里

## 受影响的用户和系统
- 用户：所有使用者，包括不会用 API 的普通用户（页面入口）
- 系统：`src/todos.py`（领域逻辑）、`src/api.py`（查询参数 + 托管页面）、`web/index.html`（页面）

## 约束
- 不破坏现有的"按优先级排序"
- 不新增任何第三方依赖（页面用原生 HTML/CSS/JS，不引框架）
- 不带 `tag` 参数时，返回结果与现在完全一致
- 页面只调现有 API，不直连存储
- 标签统一转小写存储与匹配；单条待办最多 3 个标签

## 待确认问题
已确认（2026-08-31）：
- 标签上限：单条待办最多 3 个
- 大小写：不区分，统一转小写存储与匹配
- 页面：展示"已完成"列表（只读）
无遗留问题，可进入设计。
